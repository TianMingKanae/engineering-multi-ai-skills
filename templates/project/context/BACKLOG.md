# Bounded jobs

| ID | Owner | Input revision | Command / working directory | Acceptance and artifacts | Status |
|---|---|---|---|---|---|

Use queued, running, done or blocked. Record a claim before launch and give each job a linked discussion thread. Long jobs also name their resource limit and supported resume method.

Under the governed profile, link each stable task ID to its assigned node, single-writer lease and task-level fix/retry counters in GOVERNANCE.md. Defaults are one mechanical patch and one safe retry across all nodes/wakes. A `<role>-fix:` commit requires O/F review before main launch or claim integration. Exhaustion or uncertainty blocks the job; migrations preserve counters.
