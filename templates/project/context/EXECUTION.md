# Execution packet and budget record

Use for a costly or distributed job, not every edit. Keep actual paths, machine inventories and raw private evidence in approved local storage.

| Field | Record |
|---|---|
| Stable task / accountable implementer | One current owner and thread |
| Authorized phase and decision source | Preparation or execution; no implicit release |
| Input revision / exact-byte packet / protected anchor | Declared source, configuration, helpers and evidence |
| Runtime resolution receipt | Actual executable/import versions, paths and hashes; local only |
| Checked / unchecked scope | Distinguish stored compatibility, execution and outcome quality |
| Active run root / source immutability | No pull or edits underneath live work |
| Execution release | Exact packet, target readiness, scope and required independent gate |
| Budget authority / unit / ceiling / attempt cap | One authoritative ledger; disjoint host allocations if needed |
| Reservation / stop control | Stable attempt ID and bounded launch; pending/crash stays charged |
| Settlement / evidence | Raw receipt/hash, lifetime cost ID, terminal status, measured or policy debit |
| Prior failure / new repair root | Preserve failed evidence, old costs and lineage |
| Delta review | Accepted base hash, changed invariants, new checks and unchanged evidence |
| Final outcome / limits | Job completion is not independent verification |

Helpers: [packet contract](../../../skills/execution-integrity/references/packets.md), [budget contract](../../../skills/execution-integrity/references/budgets.md). Estimates, nested diagnostics and real measurements must remain distinguishable. Do not recursively account for writing an accounting receipt.
